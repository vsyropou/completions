# Completion Protocol — FROZEN v1

Contract version: **v1.0** (frozen 2026-10-14). No field renames, endpoint changes, or coordinate changes without lead approval and a version bump.

## 1. Overview

```
VS Code <--JSON-RPC 2.0 over stdio--> Rust sidecar <--HTTP/JSON--> Phoenix
```

- All logs go to **stderr** on the Rust process. stdout is protocol only.
- Positions are **zero-based** `{line, character}` in **UTF-16 code units** (VS Code native).
- Document `version` is an integer, **monotonically increasing** per document.
- `request_id` for the HTTP hop is a UUID v4 string generated by Rust.

---

## 2. TypeScript ↔ Rust (JSON-RPC 2.0 over stdio)

### 2.1 Framing

LSP-style headers, single `Content-Length`, blank line, UTF-8 JSON body:

```
Content-Length: 87\r\n
\r\n
{"jsonrpc":"2.0","id":1,"method":"initialize",...}
```

### 2.2 Methods

Requests (need a response): `initialize`, `completion/request`, `shutdown`.
Notifications (no response): `textDocument/didOpen`, `textDocument/didChange`, `textDocument/didClose`, `completion/cancel`.

#### `initialize` — request

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "workspace_root": "file:///repo",
    "phoenix_url": "http://localhost:4000",
    "auth_token": "dev-token",
    "max_tokens": 128
  }
}
```

Response:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": { "capabilities": { "languages": ["typescript", "tsx"] } }
}
```

#### `textDocument/didOpen` — notification

```json
{
  "jsonrpc": "2.0",
  "method": "textDocument/didOpen",
  "params": {
    "uri": "file:///repo/src/main.ts",
    "language": "typescript",
    "version": 1,
    "text": "function hello() {\n}"
  }
}
```

#### `textDocument/didChange` — notification

Full-document replacement only in v1.

```json
{
  "jsonrpc": "2.0",
  "method": "textDocument/didChange",
  "params": {
    "uri": "file:///repo/src/main.ts",
    "version": 2,
    "text": "function hello() {\n  return 42;\n}"
  }
}
```

#### `textDocument/didClose` — notification

```json
{
  "jsonrpc": "2.0",
  "method": "textDocument/didClose",
  "params": { "uri": "file:///repo/src/main.ts" }
}
```

#### `completion/request` — request

```json
{
  "jsonrpc": "2.0",
  "id": 123,
  "method": "completion/request",
  "params": {
    "document_uri": "file:///repo/src/main.ts",
    "document_version": 42,
    "position": { "line": 10, "character": 8 },
    "max_tokens": 128
  }
}
```

Success response:

```json
{
  "jsonrpc": "2.0",
  "id": 123,
  "result": {
    "text": "return result;\n",
    "document_version": 42
  }
}
```

Error response (JSON-RPC standard error object):

```json
{
  "jsonrpc": "2.0",
  "id": 123,
  "error": {
    "code": -32001,
    "message": "document version mismatch: requested 42, current 43"
  }
}
```

Error codes:

| code | meaning |
|---|---|
| -32700 | parse error |
| -32601 | unknown method |
| -32602 | invalid params |
| -32000 | unknown document |
| -32001 | document version mismatch / stale request |
| -32002 | upstream (Phoenix) error |
| -32003 | cancelled |

#### `completion/cancel` — notification

```json
{
  "jsonrpc": "2.0",
  "method": "completion/cancel",
  "params": { "request_id": 123 }
}
```

The `request_id` equals the JSON-RPC `id` of the `completion/request` to cancel. Cancellation is best-effort: the extension **must** discard stale responses even if cancellation arrives late.

#### `shutdown` — request

```json
{ "jsonrpc": "2.0", "id": 999, "method": "shutdown" }
```

Response: `{ "jsonrpc": "2.0", "id": 999, "result": null }`. Rust exits with code 0 after responding. The extension then closes stdio and terminates the process if it does not exit within 2s.

## 3. Rust ↔ Phoenix (HTTP/JSON)

### 3.1 Completion endpoint

```
POST /api/v1/completions
Content-Type: application/json
Authorization: Bearer <token>
```

Request:

```json
{
  "request_id": "3f6c9b42-...",
  "language": "typescript",
  "file_path": "src/main.ts",
  "prefix": "function calculate() {\n",
  "suffix": "\n}",
  "repository_context": "",
  "max_tokens": 128
}
```

- `file_path` is repo-relative, forward slashes.
- `repository_context` may be `""` in Phase 1.
- Body size limit: **256 KB**. Phoenix responds `413` beyond it.

Success response (`200`):

```json
{
  "request_id": "3f6c9b42-...",
  "completion": "  return 42;\n",
  "finish_reason": "stop",
  "model": "mock"
}
```

`finish_reason` ∈ `"stop" | "length" | "error"`.

Error responses — consistent shape, JSON body:

```json
{ "error": { "code": "unauthorized", "message": "invalid bearer token" } }
```

| status | code | when |
|---|---|---|
| 400 | `invalid_request` | malformed JSON / missing field |
| 401 | `unauthorized` | bad/missing bearer token |
| 413 | `too_large` | body over limit |
| 422 | `validation_failed` | schema valid JSON, semantically invalid |
| 502 | `upstream_error` | inference provider failed |
| 504 | `upstream_timeout` | inference provider timed out |

### 3.2 Timeouts

- Rust HTTP client: **10 s** connect, **30 s** total.
- Phoenix inference call: **25 s**.

## 4. Coordinates and versions

- `position.line`: zero-based line.
- `position.character`: zero-based **UTF-16 code unit** offset within the line.
- Rust converts to a UTF-8 byte offset before slicing. Rust must handle multi-byte characters and surrogate pairs correctly. If a UTF-16 `character` lands mid-surrogate-pair (i.e. between the high and low halves), the position resolves to the boundary **before** the pair.
- A completion response is valid only if `document_version` in the response equals the document's current version in the extension. Otherwise the extension discards it.

---

## 5. Authentication

- Phoenix validates the `Authorization: Bearer <token>` header against a token from config (`AUTH_TOKEN` env).
- MVP = a single shared token. No user database.

---

## 6. Cancellation semantics

- VS Code `CancellationToken` → extension sends `completion/cancel`.
- Rust drops the in-flight HTTP request (abort) and replies to the JSON-RPC request with error `-32003` if it hasn't replied yet.
- Phoenix best-effort cancels the upstream HTTP call when the client disconnects (Bandit/Finch handle disconnect). GPU work may continue; that is accepted for MVP.
- The extension ignores responses for cancelled IDs.
